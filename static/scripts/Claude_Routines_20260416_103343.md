# Claude Routines 正式发布：AI自动化平台的革命性一步

大家好，欢迎收听本期播客。今天我们要聊一个重磅更新——**Anthropic公司刚刚发布了Claude Routines功能**。这可不是一个小打小闹的升级，在我看来，它彻底改变了游戏规则，直接把Claude从一个对话式AI，变成了一个**完整的自动化平台**，开始正面竞争那些我们熟悉的无代码拖拽式工具，比如N8N、Make.com等等。

简单来说，Routines允许Claude通过**计划任务、触发器或者Webhook**来启动自动化流程。这意味着什么？意味着**闭环完成了**。AI不再只是回答你的问题，而是可以主动为你干活，而且是按部就班、有条不紊地干。

## 一、 Routines到底是什么？一个活生生的例子

可能光说概念有点抽象，我直接给大家演示一个我最常用的、也最典型的例子：**每日邮箱摘要和草稿撰写自动化**。

我的工作邮箱每天都会收到很多邮件，有些是合作邀请，有些是粉丝提问，有些是会议邀约。以前我得自己一封封看，再决定怎么回复，挺耗时间的。现在，我用Claude Routine把这个过程自动化了。

**我是怎么做的呢？**

我创建了一个Routine，给它的指令（或者说“提示词”）大概是这样的：
1.  **连接我的Gmail**，拉取所有未读邮件。
2.  对于每一封未读邮件，**检查之前是否和这个联系人有过邮件往来**。如果有，把历史记录也调出来，提供上下文。
3.  根据你对我的了解（比如我的说话风格、业务范围）以及邮件的具体内容，**为每一封邮件起草一个回复草稿**。
4.  所有草稿起草完成后，**使用Slack连接器，给我发一条通知**，把摘要和草稿内容发给我。

设置好之后，我可以选择让它**每天定时运行**，比如设定在我每天起床前——早上5点10分。这样我一睁眼，就能在Slack上看到整理好的邮件摘要和已经写好的回复草稿。我只需要快速浏览一下，点击“发送”或者稍作修改就行，效率提升了不止一个量级。

你可能会问，这和我自己用Claude聊天让它帮我写邮件有什么区别？区别太大了！**关键就在于“自动化”和“代理化”**。

*   **自动化**：我不需要每天早上去手动触发这个流程。它就像个忠实的助手，到点就上班，风雨无阻。
*   **代理化**：Claude在这个流程里扮演了一个“代理”的角色。它不只是生成文本，而是会**调用一系列工具**——访问Gmail API、查询历史记录、分析内容、生成文本、调用Slack API发送消息。这一连串的动作，它自己就完成了。

而且，这一切都运行在**云端的标准化的Claude容器**里，不在我的本地电脑上。所以它不占用我的计算资源，我也不需要一直盯着它。我只需要把指令写清楚，确保它拥有完成任务所需的所有信息（比如Gmail和Slack的访问权限），然后就可以放手让它去干了。

## 二、 不仅仅是邮件：从会议转录到商业提案

当然，Routines的能力远不止处理邮件。让我再分享一个更酷的用例：**将会议录音自动转化为商业提案**。

我的工作流程是这样的：
1.  我使用一个叫Fireflies.ai的工具参加会议。它会自动录音、转录，把整个会议的文本内容保存下来。
2.  会议结束后，Fireflies.ai会通过一个**Webhook**（网络钩子）自动触发我设置好的Claude Routine。
3.  Routine收到包含会议转录文本的Webhook后，开始工作。它的指令是：“根据这份会议录音转录稿，结合我们公司的服务模板，生成一份完整的、定制化的商业提案。”
4.  生成完成后，它同样可以通过Slack通知我，或者直接保存到Google Docs，甚至发送给客户。

这个过程里，最厉害的点在于 **“托管会话”** 的运用。我可以让这个Routine去调用我另一个专门训练过的、用于生成提案的AI代理。这就形成了一个**AI代理网络**：一个Routine作为调度中心，根据不同的任务，去调用不同的专业AI代理。每个代理都在自己安全的、隔离的容器环境中运行，既保证了能力专精，又确保了安全性。

想想看，以前要完成这样一个从会议到提案的自动化流程，你需要：
*   在Fireflies设置Webhook输出。
*   在N8N或Zapier里创建一个复杂的流程，接收Webhook。
*   设计一堆节点来处理转录文本：提取关键信息（客户需求、预算、时间线）、匹配提案模板、填充内容、格式化……
*   最后再设置一个节点，把生成的提案发送到指定位置。

每一步都需要拖拽节点、配置API密钥、映射数据字段，非常繁琐。而现在，**你只需要用自然语言告诉Claude Routine“该做什么”**。剩下的“怎么做”，它自己会搞定。

## 三、 新旧对比：为什么说这是革命性的？

为了让大家更清楚Routines带来的改变，我们来对比一下自动化任务的“旧方法”和“新方法”。

**旧方法（以N8N为例）：**
1.  **事件触发**：比如一个定时器（每天早上5点），或者一个Webhook（收到新邮件）。
2.  **复杂逻辑构建**：你需要进入N8N的画布，从左侧拖拽各种各样的功能节点到中间：HTTP请求节点、Gmail节点、文本处理节点、条件判断节点、数据转换节点等等。然后用线把它们连起来，形成一个工作流。
3.  **繁琐配置**：每一个节点你几乎都要配置：API端点、认证信息（API密钥、OAuth）、输入输出字段的映射关系。这个过程非常细致，也很容易出错，是自动化搭建中最耗时、最需要专业知识的“硬骨头”。
4.  **输出结果**：最后，工作流会把处理结果推送到某个地方，比如Slack、CRM系统或者数据库。

**新方法（使用Claude Routines）：**
1.  **事件触发**：一模一样。可以是定时、API调用或Webhook。
2.  **逻辑构建**：**用自然语言写一份“说明书”**。就像我前面写的：“拉取未读邮件，检查历史，起草回复，发Slack通知。” 你不需要知道Gmail API的细节，不需要设置条件节点，你只需要用人类语言描述任务。
3.  **配置简化**：你主要需要做的是“连接器”的授权。比如告诉Claude“你可以访问我的Gmail和Slack”。这是一次性的、简单的OAuth授权点击，远比配置API密钥简单。
4.  **输出结果**：一模一样。结果可以发送到任何连接器支持的地方。

**看出区别了吗？Routines革命性地解决了中间那个最复杂的环节——逻辑构建。** 它用“自然语言编程”替代了“拖拽节点编程”。这大大降低了自动化的门槛。你不需要是一个懂技术的开发者，只要你善于清晰地描述任务，你就能构建强大的自动化流程。

这也是为什么我说，**Routines是N8N这类工具的直接竞争对手，甚至是“平替”**。它在功能上实现了高度重叠：都能调度、都能编排工作流、都能集成各种应用。但它的入口更友好，构建速度更快。

## 四、 手把手教你创建第一个Routine

说了这么多，可能你已经摩拳擦掌想试试了。别急，我带你快速走一遍创建流程，非常简单。

1.  **访问入口**：打开浏览器，访问 `claude.ai/code/routines`。你会看到一个仪表盘，这里列出了你所有的Routine，可以看到它们的名称、下次运行时间等。也有日历视图，一目了然。
2.  **点击“新建”**：在右上角找到“New Routine”按钮。
3.  **填写基本信息**：
    *   **名称**：给你的Routine起个名字，比如“晨间邮件助手”。
    *   **描述**：**这是核心！** 在这里用自然语言详细描述Claude该做什么。记住一个原则：**尽可能清晰和精确**。因为Routine是“放手不管”的全自动运行，不像聊天可以随时纠正。所以指令要减少歧义，明确步骤。比如：“使用Gmail连接器，获取我的所有未读邮件。对每一封，搜索与该联系人的历史邮件以获取上下文。然后，以我通常专业且友好的口吻，为每封邮件起草回复草稿。完成后，使用Slack连接器，将邮件摘要和草稿内容发送到我的Slack私信。”
4.  **选择模型和环境**：你可以选择使用哪个Claude模型（比如强大的Opus），以及运行在哪个云端环境（环境里可以预置一些API密钥等变量）。
5.  **设置触发器**：选择如何启动它。
    *   **定时**：选择每天、每小时等，并设置具体时间。
    *   **API调用**：系统会生成一个唯一的API端点（URL）和调用示例（cURL命令）。你可以用任何能发送HTTP请求的工具或程序来触发它。
    *   **Webhook**：同样会提供一个URL，等待外部服务来“敲门”。
6.  **添加连接器**：这是让Claude访问外部服务的“钥匙”。点击“添加连接器”，你可以搜索并连接Gmail、Slack、Notion等上百种工具。通常只需要点几下，完成OAuth授权即可。
7.  **测试与保存**：点击右上角的“立即运行”，可以先手动测试一次，看看流程是否顺畅，结果是否符合预期。没问题的话，保存即可。

看，整个过程，**你没有写一行代码，没有拖拽一个节点**，一个自动化助手就诞生了。

## 五、 更强大的潜力：无缝迁移与动态修改

Routines还有一个让我惊叹的特性：**它很容易与你现有的工作流集成，甚至能动态修改自身**。

**迁移现有工作流**：假设你已经在N8N上搭建了一个很棒的自动化流程，比如从Hacker News抓取热门AI故事，然后生成报告。在N8N里，这个流程可能由十几个节点组成。现在，你可以**直接复制这个流程的JSON代码**，把它粘贴给Claude，并说：“请用Routine生成器，把这个N8N工作流转换成一个Claude Routine。” 几秒钟后，一个功能相同的Routine就创建好了。这为从传统无代码平台迁移提供了捷径。

**动态修改与迭代**：传统的自动化流程，修改起来很麻烦。比如，我想让上面那个Hacker News抓取流程在完成后，额外给我发个Slack提醒。在N8N里，我得回去找到流程，拖入一个Slack节点，正确连线，配置好。而在Claude这边，我只需要**在聊天窗口里对那个Routine说一句**：“嘿，更新一下，完成后把报告用Slack发给我。” 它就能自动去修改Routine的配置，添加Slack连接器和发送步骤。这种用对话来维护和迭代自动化流程的能力，是前所未有的便捷。

## 六、 展望未来：商业自动化的新范式

那么，Routines到底能为我们做什么？它的想象空间非常大。在我自己的业务和团队中，我已经在规划和实施这些用例：

*   **销售流程全自动化**：客户咨询 → 自动生成初步回复并预约会议 → 会议后，根据转录自动生成提案和跟进邮件 → 客户签单后，自动触发 onboarding 流程，发送欢迎邮件、安排启动会议。
*   **内容与运营自动化**：监控社交媒体提及，自动生成回复或报告；定期抓取行业新闻，生成简报；处理用户反馈，自动分类并提交给相应部门。
*   **内部协作自动化**：代码提交后自动进行初步审查；项目管理工具中的状态更新自动同步到团队聊天群；新员工入职自动分配任务和资源。

**本质上，你现在可以自动化商业中几乎所有不需要“真人面对面沟通”的环节。** 以前不是不能做，而是做起来很费力，需要专门的知识。现在，只要你理解业务逻辑，并能清晰地描述出来，Claude Routines就能帮你实现它。

当然，它目前可能还不适合完全替代所有极其复杂、高频率、对成本极其敏感的巨型工作流（毕竟AI按Token计费）。但对于大量的、中小型的、价值高的自动化需求，Routines提供了一个极其高效和易用的解决方案。
